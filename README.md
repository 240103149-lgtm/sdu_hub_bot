# University AI Knowledge Hub — Telegram бот + сайт

Бір білім қоры, бір промпт, екі интерфейс:

```
core.py            ← бүкіл логика: knowledge/ оқу, Gemini, қателер, тілдер
├── telegram_bot.py  Telegram боты (handler-лер)
│   └── bot.py       polling режимінде іске қосу  →  python bot.py
└── main.py          сайт + REST API (+ webhook)  →  uvicorn main:app --reload
```

Бот пен сайт бір `core.py`-ды қолданады, сондықтан екеуі әрқашан **бірдей
құжаттардан бірдей жауап** береді. Жаңа мүмкіндікті бір жерге қоссаң,
екеуінде де жұмыс істейді.

## 1. Орнату

```bash
pip install -r requirements.txt
cp env.example .env        # Windows: copy env.example .env
```

`.env` файлын ашып толтыр:

| Айнымалы | Қайдан аласың |
|---|---|
| `GEMINI_API_KEY` | https://aistudio.google.com/apikey |
| `GEMINI_MODEL` | мысалы `gemini-flash-latest` |
| `TELEGRAM_BOT_TOKEN` | Telegram-дағы **@BotFather** → `/newbot` |

> ⚠️ Бұрынғы кілтің чатқа жүктелген `.env` файлында ашық тұрды — AI Studio-да
> оны өшіріп, жаңасын жасап ал.

Жобаны git-ке қоссаң, түбірде `.gitignore` файлын жаса:

```gitignore
.env
bot_state.pickle
__pycache__/
*.pyc
```

`.env` бір рет коммитке түссе, кейін өшірсең де git тарихында қалады —
сондықтан алдымен `.gitignore`.

Файлдар өзгергенде автоматты түрде қайта оқылады — серверді қайта қосудың

my.sdu.edu.kz-тегі ашық Student Handbook пен ережелер PDF-інен, 18.10.2026

| :---- | :---- |

## 4. Сайтты іске қосу

```bash
uvicorn main:app --reload
```

→ http://127.0.0.1:8000

| Endpoint | Не қайтарады |
|---|---|
| `GET /` | `static/index.html` |
| `POST /api/chat` | `{message, history, lang}` → `{reply}` |
| `GET /api/guide?lang=kk` | нұсқаулық мәтіні |
| `GET /api/health` | сервер тірі ме, қандай құжаттар көрінеді |

`/api/health` — демо алдында тексеруге ыңғайлы: `documents` тізімі бос болса,
`knowledge/` папкасы бос деген сөз.

Бот пен сайтты **бір уақытта** қосуға болады — екі бөлек терминал:

```bash
python bot.py                    # 1-терминал
uvicorn main:app --reload        # 2-терминал
```

## 5. Webhook режимі (серверге шыққанда)

Ноутбукте polling жеткілікті. Хостингке (Railway, Render, VPS) қойғанда бір
ғана процесс сайтты да, ботты да ұстай алады:

```ini
TELEGRAM_MODE=webhook
TELEGRAM_WEBHOOK_URL=https://sening-domenin.up.railway.app
TELEGRAM_WEBHOOK_SECRET=кездейсоқ_ұзын_жол
```

Сосын тек `uvicorn main:app --host 0.0.0.0 --port $PORT` қосасың — `bot.py`
керек емес. Webhook-ты Telegram-ға тіркеу автоматты түрде жүреді.

`TELEGRAM_WEBHOOK_SECRET` — Telegram әр сұраныста қайтаратын құпия жол;
онсыз webhook-қа кез келген адам жалған хабар жібере алады.

## 5.1. Vercel-ге деплой

Vercel — serverless: тұрақты процесс жоқ, әр сұраныс жеке, қысқа өмір
сүретін функцияда өңделеді. Сондықтан:

- **`python bot.py` (polling) Vercel-де мүлде істемейді.** Тек
  `TELEGRAM_MODE=webhook` арқылы жұмыс істейді.
- **`bot_state.pickle` тұрақты сақталмайды.** Vercel-дің файл жүйесі
  тек `/tmp`-ке жазуға рұқсат етеді, ол да cold start сайын өшіп кетеді.
  Яғни пайдаланушының тілі/тарихы уақыт өте келе жоғалуы мүмкін — бот
  құламайды, бірақ жады тұрақты емес. Толық шешім — сыртқы қойма (Redis,
  Vercel KV) қолдану, ол осы жобада әлі жоқ.
- **Webhook-ты бір рет қолмен тіркеу керек.** ASGI `lifespan` startup
  оқиғасы Vercel-де әр cold start сайын шақырыла бермейді, сондықтан
  автоматты тіркеуге сенбе:

  ```bash
  python scripts/register_webhook.py https://your-app.vercel.app
  ```

  Деплой URL-ы өзгерген сайын осыны қайта қос.

**Қадамдар:**

1. Vercel жоба баптауларында (Project → Settings → Environment Variables)
   мыналарды қос: `GEMINI_API_KEY`, `GEMINI_MODEL`, `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_MODE=webhook`, `TELEGRAM_WEBHOOK_URL` (өз Vercel домениің),
   `TELEGRAM_WEBHOOK_SECRET`, қажет болса `REGISTRATION_PORTAL_URL`.
2. Vercel-ге push жаса (`vercel.json` + `api/index.py` осы репода бар,
   Vercel оларды автоматты таниды).
3. Деплой аяқталғаннан кейін `python scripts/register_webhook.py
   https://<деплой-домені>` қос.
4. `https://<деплой-домені>/api/health` ашып, сервер тірі екенін тексер.

## User story-лерге сәйкестік

Тексерулер: `tests/test_user_stories.py` (US1–US7 QA сценарийлері),
`tests/test_documents.py` (US8), `tests/test_i18n.py` (US6).

### US1 — AI чатбот (QA: US5QATest)

| Талап | Қайда орындалған |
|---|---|
| Еркін мәтінмен сұрақ | `telegram_bot.on_question`, `POST /api/chat` |
| Тек бекітілген білім қоры (RAG) | `core.SYSTEM_PROMPT` + `core.load_knowledge()` |
| Жауап табылмаса — fallback | Модель дәл осы сөйлеммен жауап береді: «I don't have this information, please contact the administration» (сұрақтың тілінде) |
| «Connection error» ескертуі | Сервер қолжетімсіз болса **немесе 5 секундта жауап болмаса**, бот күтуді тоқтатып, «Connection error» көрсетеді |
| 5 секунд ішінде жауап | `RESPONSE_BUDGET_SECONDS=5` — қатаң шек; `SLOW_RESPONSE_SECONDS` — әр жауап уақыты терминалда жазылады |

Терминалдағы лог тест есебіне тікелей қоюға жарайды:

```
[core] answered in 2.3s (target 5s)
[core] no answer within 5s - stopped waiting (US1: Connection error)
```

Модель 5 секундқа үлгермесе, `.env`-те `RESPONSE_BUDGET_SECONDS`-ты көбейтуге
болады — бірақ сонда US1 талабы орындалмайды.

### US2 — Расписание құру нұсқаулығы (QA: US3QATest)

`/guide` командасы `knowledge/registration_guide.<lang>.md` файлын көрсетеді
(кестелер, сілтемелер Telegram-да да, сайтта да дұрыс шығады).

- Файл жоқ болса — «Guide not available for this semester…», **басқа
  семестрдің нұсқаулығын көрсетпейді**.
- Файл бар, бірақ оқылмаса — «Registration guide is temporarily unavailable.
  Please try again.» және 🔄 Retry батырмасы (сайтта да).
- Портал батырмасы әрдайым бар: әдепкі `https://my.sdu.edu.kz/`,
  `.env`-тегі `REGISTRATION_PORTAL_URL` оны ауыстырады.

### US3 — Бос кабинеттер (QA: US1QATest)

`/rooms 20.10 14:00-16:00` — сол күні **бүкіл аралықта** бос кабинеттер
(сабақ дәл басталу уақытында аяқталса немесе дәл аяқталу уақытында басталса,
қиылыс емес). Нәтиже ғимарат бойынша топталады, «Available according to
schedule» деп белгіленеді және кесте дерегінің күні көрсетіледі
(`data/schedule_meta.json` — кестені ауыстырғанда осы күнді де жаңартыңыз).
Қате сұрау, бос кабинет жоқ және дерек жүктелмеуі — үш бөлек хабарлама;
соңғысында Retry таңдалған күн мен уақытты сақтайды.

### US4 — Кампус ивенттері (QA: US2QATest)

`/events` — жарияланған ивенттер күні мен уақыты бойынша; `/events 01.11-30.11`
— тек сол аралықта басталатындары. ℹ️ батырмасы толық мәліметті ашады.
Ұйымдастырушы `knowledge/campus_events.md` ішінде `- Status: Cancelled /
Postponed / Draft` және `- New date: …` жаза алады: draft көрсетілмейді,
шегерілген ивентте жаңа күні не «New date to be confirmed» шығады. Уақыты не
орны жарияланбаса — «To be confirmed». Дерек оқылмаса — Retry.

### US5 — Бағалар мен транскрипт (QA: US4QATest)

Жарияланбаған баға (бос немесе «IP») — «Not published», ешқашан 0 емес.
Портал жауап бермесе — «Academic records are temporarily unavailable…» және
Retry (кэшті емес, порталды қайта сұрайды). Жазба жоқ болса — «No academic
records available».

### US6 — Үш тіл (QA: US6QATest)

Интерфейстің барлық мәтіні — `locales/kk.json`, `locales/ru.json`,
`locales/en.json` (бот та, сайт та). Мәтінді өзгерту үшін тек JSON-ды
түзетесіз; `tests/test_i18n.py` үш файлдың кілттері мен `{placeholder}`-лері
бірдей екенін тексереді.
Бірінші рет `/start` басқанда бот ағылшынша ашылады, Telegram баптауындағы
тілге тәуелсіз. `/lang` арқылы таңдалған тіл сақталады; жеке чаттағы командалар
мәзірі де таңдалған тілге ауысады. Gemini студент қай тілде жазса, сол тілде жауап береді —
құжаттар басқа тілде болса да.

### US7 — Жүйеге кіру (QA: US7QATest)

- `/login` — университет ID-і (студент нөмірі) мен портал паролі, қажет болса
  поштаға келген код; сәтті болса, жеке негізгі мәзір ашылады. Пароль тек
  my.sdu.edu.kz-ке жіберіледі, хабарлама бірден өшіріледі, ешқайда сақталмайды.
- Қате пароль — «Invalid credentials…» және қалған әрекет саны. Бір аккаунтқа
  қатарынан 5 қате — 15 минутқа «Account temporarily locked»: бұл уақытта
  пароль сұралмайды, порталға сұрау жіберілмейді (Moodle кіруі де солай).
  Баптаулар: `LOGIN_MAX_FAILURES`, `LOGIN_LOCK_MINUTES` (`env.example`).
- Әр кіру уақыты 3 секундтық мақсатпен терминалда жазылады:
  `[auth] portal password check: 1.4s (target 3s)`.

### Әлі деректі қажет ететіндер

Бұларды кодпен ойдан шығаруға болмайды — университеттен дерек керек:
басқа семестрлердің нұсқаулығы және оның қазақша/орысша нұсқасы (US2);
кабинеттердің қабаты, сыйымдылығы, броньдары мен жабылуы (US3); алдағы
ивенттер — қазіргі бес ивенттің бәрі өтіп кеткен (US4); сайтта кіру беті жоқ
(US7, бот арқылы ғана).

### US8 — Құжат тапсыру (Document Submission)

`/documents` немесе мәзірдегі «📄 Құжаттар» батырмасы жаңа студентке оқуға қабылдау
құжаттарын бот арқылы тапсыруға мүмкіндік береді. Тек жеке чатта жұмыс істейді.

| Талап | Қайда орындалған |
|---|---|
| Алғышарт: белсенді аккаунт | Құжаттар портал аккаунтына (студент нөміріне) тіркеледі. Портал байланыспаған болса, `/documents` алдымен ортақ портал кіруін ұсынады (`accounts_bot`), кірген соң тізім өзі ашылады |
| Міндетті құжаттар тізімі | `data/required_documents.json` — SDU ресми бетінен: [sdu.edu.kz/en/admission-3-2](https://sdu.edu.kz/en/admission-3-2/). Грант (9 міндетті) және ақылы оқу (9 міндетті) бөлек; «қажет болса» құжаттары тапсыруды бұғаттамайды |
| Формат дұрыс болмаса ескерту | `documents.check_file()`: PDF, JPG, PNG (фото 3×4 — тек JPG/PNG), ең көбі 10 МБ; кеңейтім мен MIME түрі сәйкес болуы керек. Қате файл сақталмайды |
| Құжат жетіспесе ескерту және бұғаттау | `DocumentStore.submit()` → «Please upload the missing document: …», мәртебе өзгермейді (QA сценарийі 2) |
| «Submission successful» | Барлық міндетті құжат жүктелгенде «📤 Тапсыру» (QA сценарийі 1) |
| Мәртебе нақты уақытта | Әр жүктеуден кейін тізім жаңа мәртебемен қайта шығады; қабылдау комиссиясы ✅/❌ басқан сәтте студентке хабарлама келеді, бәрі қабылданса — «🎉 … аяқталды» |
| Мәртебе айнымалылары | Файл: `uploaded → under_review → verified / rejected` (жаңасы жүктелсе — `replaced`); өтінім: `draft`, `under_review`, `needs_correction`, `verified` |
| Тапсырылған құжаттар кестесі (БД) | SQLite: `submissions`, `submitted_documents` (`data/documents.db`, git-ке түспейді). Әр жүктеу жаңа жол — тарихы сақталады |
| DMS stored procedures | `DocumentStore` әдістері (`start`, `save`, `submit`, `review`, `get`, `pending_reviews`) — әрқайсысы бір транзакция, бір процедураға сәйкес. Университеттің нақты DMS-і қосылғанда тек осы класс ауысады |

**Қабылдау комиссиясы.** `.env` ішінде `DOCUMENTS_REVIEWER_IDS=123456789,987654321`
(Telegram user ID, үтірмен; әрқайсысы ботқа бір рет `/start` басуы керек). Тапсырылған
әр файл оларға «✅ Қабылдау / ❌ Қабылдамау» батырмаларымен келеді; қабылдамаса,
себебін таңдайды (оқылмайды / басқа құжат / толық емес не мерзімі өткен). `/review` —
тексеруді күтіп тұрған файлдарды қайта жібереді. Тізім бос болса, құжаттар
«тексерілуде» күйінде қала береді (Deferred сценарийі).

**Бұл — оқу прототипі.** Бот алғашқы экранда да, әр тізімнің астында да
құжаттар SDU-ға ресми түрде жіберілмейтінін, ресми тапсыру admissions.sdu.edu.kz
және Қабылдау комиссиясы арқылы жүретінін айтады. Демода шын құжаттарды
(әсіресе 075, флюорография сияқты медициналық анықтамаларды) емес, тест
файлдарын жүктеңіз. Шын студенттерге іске қосу үшін алдымен университетпен
(Қабылдау комиссиясы, IT бөлімі) келісу және дербес деректерді қорғау керек.

**Шектеулер.** Файлдың өзі Telegram серверінде қалады, базада тек `file_id` пен
сипаттамасы сақталады; сондықтан бот токенін ауыстырсаңыз, ескі файлдар ашылмайды.
Университеттің DMS-і мен admissions.sdu.edu.kz-ке қосылу әлі жоқ — олардың API-ы
берілгенде `DocumentStore` соларға жалғанады. Vercel-де база `/tmp`-те, cold start
кезінде өшеді; тұрақты хостинг керек. Құжаттар тізімі өзгерсе, тек JSON файлын
жаңартыңыз (`checked` күнін де).

## Біріктірілген бот

Барлық команда бір `TELEGRAM_BOT_TOKEN` және бір `build_application()` арқылы
жұмыс істейді. Іске қосу: `python bot.py`; webhook режимінде `main.py` сол
ботты қолданады. Қосымша бот процесін іске қосудың қажеті жоқ.

- `/deadline`: Moodle аккаунтына жеке чатта кіру, дедлайндарды мерзімі бойынша
  көрсету. Пароль сақталмайды; сессия ғана сақталады. `/unlink_moodle` оны өшіреді.
- `/events`: `knowledge/campus_events.md` ішіндегі барлық жарияланған ивент.
  Мәртебесі кампус күнтізбесі бойынша есептеледі. Конференцияның өтініш дедлайны
  мен ивенттің күні бөлек көрсетіледі. Мәлімет түпнұсқаның тілінде, мәртебе мен
  интерфейс `/lang` тілінде. Бұл команда Gemini сұрауын жібермейді.
- `/rooms` немесе `/room`: `data/schedule.json` кестесі бойынша бос кабинеттер.
  `/rooms 14:30` және күн/сабақ уақыты батырмалары бар. Бұл тек сабақ кестесінің
  есебі: нақты броньдар мен аудиторияның физикалық қолжетімділігі кірмейді.
  Жаңа семестрде кесте файлын жаңарту керек.
- `/grade` пен `/deadline` ортақ кіру диалогын қолданады. Бірінен екіншісіне
  ауысқанда алдыңғы кіру тоқтайды. `/events`, `/rooms`, `/help` сияқты басқа
  командалар да кіруді аяқтап, өз әрекетін орындайды. `/cancel` — тоқтату.

Тексеру (нақты аккаунт пен API кілтінсіз, сыртқы сервистерге сұраусыз):

```bash
python -m unittest discover -s tests -v
```

Commit/branch дереккөздері мен өзгерістер: [INTEGRATION.md](INTEGRATION.md).

## Қолайлы негізгі мәзір

`/start` оқу, кампус, оқуға қабылдау және баптаулар бөлімдерін көрсетеді. Оның
астындағы жеті батырма дедлайндарды, бағаларды, ивенттерді, бос кабинеттерді,
кесте құру нұсқаулығын, құжат тапсыруды және тіл таңдауды ашады (екі бағанмен,
тіл — соңғы жолда). Команданы қолмен теру міндетті емес.
`/help` ішінде әңгіме тарихын тазарту, кіруді тоқтату және аккаунттарды ажырату
командалары жеке бөлімге жинақталған. Тілді ауыстырғанда негізгі мәзір де сол
тілде қайта көрсетіледі. Бағалар мен Moodle кіруі тек жеке чатта орындалады.
